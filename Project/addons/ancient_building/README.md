# AncientBuilding

在仓库根目录用 Git Bash 运行 `./edit.sh`，打开编辑器的 **AncientBuilding** 面板。本轮街屋参考选 **DA_RiversideShop_A / DA_RiversideHouse_A / DA_RiversideHall_A**，分别展示席棚店铺、板棚民居、花脊楼阁；此前的参考楼阁、灰墙民居、茅屋、塔仍见下表。十五个样例均可在面板载入对应预设并烘焙；也可用下文生产 CLI 的 `bake` 命令。已有烘焙场景可在 3D 视口选择单个构件。更新后重启编辑器，旧场景须重新烘焙。运行时装配体见下文 **运行时节点**：先烘焙 `.tres`，再由 `AncientBuilding`/`AncientBuildingBatch` 引用。

**建筑形制**页可改开间数、每间面阔、进深、层数、屋顶和木作材质。预览内左键拖动环绕，滚轮缩放，Shift 加左键平移。**当前建筑**页管理手动追加的摆放；烘焙后的场景包含全部自动生成的叶件。Convert 按键合为 MultiMesh，Revert 从描述还原。保存预设写回当前 JSON。

**生成方式**可选矩形建筑、多边形塔或线段连体。矩形的硬山/悬山/庑殿/歇山均支持 1–8 层；塔支持正 4–8 边、1–8 层。收进过大导致顶层不足时会报错，须减小收进或增大底层尺寸。上层柱下不生成石础。构建失败保留最后有效预览，错误修复前不能烘焙。CLI 输入不自动修正。

参数预览使用后台布局/几何计算，主线程分帧提交 Mesh 和节点。持续拖动或按住数值增减键时延后提交；松开并短暂停顿后更新。计算期间旧预览可以继续旋转，新输入会淘汰旧任务结果。点击 **构建预览** 可立即排队；**烘焙场景 / Convert** 遇到未完成输入时等待最新有效结果，不保存过时画面。

改种子、强度或固定状态会原位更新控件，保留线段画布的选择、缩放、位置和撤销记录。未变化构件复用节点，近期网格保留有预算的缓存；连体仅对自身或空间邻居变化的片段重算裁切。Stats 显示端到端等待时间、后台耗时、复用节点数、新网格数及主线程提交的单帧峰值；这不是 GPU 帧率统计。首次复杂网格仍可能需要数秒，但计算期间不会整段占住主线程；单个大网格的资源提交无法在中途切开，3 ms 分帧预算不是严格的帧时间上限。

本轮保持原有默认渲染方式：不会自动 Convert，不降低阴影或 SSAO，也未改为静止时停渲染。详细线程与更新规则见 Temp §11.5。

## 构造、几何破损与连体

在 **建筑形制** 选择 **土混木 / 纯木板围护 / 垒木围护**，屋面可独立选瓦顶或茅草顶。墙厚、板宽、垒木层高在 **比例与部件变体** 中调整。垒木有真实横向圆木截面，以框架收边，未复原井干互咬榫；木样式仍保留石台基和首层柱础。

同一区域的 **几何破损强度** 是总开关，木件/墙体/瓦件/石作倍率乘在总强度上；还可调缺口深度和受损密度。种子改变实际凹损分布，0 强度保留完好网格。手动部件暴露 `damage`、`damage_depth`、`damage_density`、`damage_seed`；当前 31 类部件支持。实现为顶点凹损与边缘变形，没有物理倒塌、掉落或贯通裂洞；外部替换 Mesh 保持原样。

选 **线段连体** 后：

1. **连续绘制**：点击空白建点，点击已有点连接，右键结束当前链；可用网格与 45° 吸附。
2. **选择/拖动**：拖动节点或在属性区输入 X/Z；点击中心线选段，分别设置宽度、层数、每层高度、构造、覆盖、悬山/庑殿，以及敞侧连廊。
3. 滚轮缩放、中键平移；按钮或 Ctrl+Z/Ctrl+Y 撤销/重做，Delete 删除。删除节点同时删除相接段。
4. 保存预设并烘焙。相交体量统一求解内墙、楼面与屋面，补脊帽、天沟和高墙挡水收边；各自独立的建筑应保持分开，仅让连廊接在预期入口。

连体支持 1–16 段、最多 32 节点；长 2–60 m、宽 2–10 m、层高 2.4–4.5 m。塔和连体以外壳与可见接点为主，没有内部楼梯、承载验算或完整历史梁架。详细契约、最终画面及限制见 `Wiki/Temp/008-AncientBuilding.md` §5.8、§8。

## 比例与部件变体

在 **建筑形制** 页向下滚动到 **比例与部件变体**：

1. 点击 **下一个种子变体**。首次会设强度为 0.65，此后每次递增种子；也可直接输入种子和 0–1 强度。
2. 调整台高、柱高/柱径、出檐、屋顶高深比、翼角、瓦垄间距、檐椽间距/半径。翼角只作用于当前支持的庑殿/歇山坡面。
3. 选择四种格心，以及各三种挂落、瓦当纯 PCG 样式，调整棂数/棂宽和挂落高度，独立开关灯笼与挂落。
4. 修改某项会自动勾选 **固定**，之后换种子保留此值；取消固定后重新接受种子控制。**恢复原始默认** 清除固定值与变体设置。
5. **保存预设** 保留种子和固定参数，再 **烘焙场景** 保存生成结果。关闭编辑器后也能用同一输入复现；不需要外部 Mesh。

种子改变整栋协调的比例与有限纹样，不随机移动柱梁，也不随机破坏对称性。字段为 `building.variation={seed,amount}` 和 `building.details`；默认强度为 0；旧预设仍可读取，新版曲面与材质修正会改变重新生成的外观。手动追加的单件仍可在 **当前建筑** 中编辑自己的 `pattern` 等 schema 参数，格心 `pattern=3` 为方格；`window=1` 是无裙板的通格窗，其他纹样保持 0/1/2。完整宋式梁架与长昂仍见 Temp §10.1、§17，本轮变体不能当成历史复原。

**v13 构件细化**仍在同一组控件中调整：

| 面板参数 / 字段 | 范围与默认值 | 实际作用 |
| --- | --- | --- |
| 铺作出跳 `bracket_projection` | 0.24–0.60 m，默认 0.36 | 改变出跳栱和昂的伸出量；柱头、补间和角部共用承托标高 |
| 补间铺作 `bracket_density` | 仅柱头与转角 / 开间增加一攒；殿阁和门楼默认增加 | 矩形开间中增加补间组合，角部使用独立合并承托形状 |
| 木件倒角 `joinery_bevel` | 0–0.012 m，默认 0.004 | 梁、枋、斗、栱、昂的受限可见边倒角 |
| 柱身梭度 `column_entasis` | 0–0.06，默认 0.015 | 改变柱身中段鼓出，不移动上下安装面 |
| 柱头收分 `column_taper` | 0–0.14，默认 0.09 | 改变柱顶与柱脚的半径比例 |
| 脊饰浮雕强度 `ornament_relief` | 0–1，默认 0.6 | 改变吻兽躯干浮雕与鸱尾羽脊的实际几何 |
| 脊饰卷尾程度 `ornament_curl` | 0.65–1.25，默认 1 | 改变两种母型上部走势与卷尾轮廓 |

F04 梁改为 P 策略，梁头、梁肩按实际跨度生成，短梁自动采用有效矩形截面；F02 额枋继续使用 S 策略。斗具有真实十字槽，栱采用连续卷杀轮廓；矩形和塔的檐下高度根据承托尺寸调整，上层无石基规则保留。脊端仍通过“兽饰 / 扇形鸱尾”选择母型，手动 R11/R12 的 `style=0/1` 对应两类，安装底面统一在 Y=0。它们是独立程序实现，未导入 ACA 模型，不代表完整历史形制复原。

## 街屋、轻棚与纹路

加载上述 Riverside 预设后，在 **建筑形制 → 比例与部件变体** 调整：

| 效果 | 面板参数 |
| --- | --- |
| 席棚、板棚或只有棚杆 | 临街棚架；棚面出挑、棚后缘离台高、棚前缘降高、棚覆盖开间（0 为全部，否则居中） |
| 细立杆或墙侧悬挑 | 棚架承托；棚高以台面为基准，台基外立杆落到地面 |
| 柔软席面与编织 | 席面下垂、席面纹路（顺排苇席 / 经纬编织 / 斜编席）；四边保持支承位置，板棚用真实板缝与参差板端 |
| 脊的厚薄、端部走势 | 脊身样式（圆盖素脊 / 薄压脊 / 高身灰脊 / 连弧花脊）、正脊高度 / 宽度 / 分节间距、脊端生起、垂戗脊宽 |
| 瓦面、梁枋的节奏 | 铺瓦纹路（筒板瓦 / 错缝板瓦 / 鳞叠板瓦）、梁枋线饰（素木 / 细线饰 / 几何菱带） |

正脊高度最低 0.10 m、宽度最低 0.14 m；压瓦底脚独立保留，并限制山尖垂脊高度，避免薄脊露出交接构件。花脊有真实透孔与连续压顶；分节间距同时控制花脊孔距。席面粗起伏、下垂、板缝、铺瓦形状和花脊均改变实际几何；细编织、梁枋线饰与新 PBR 材质共同表现细节，默认贴图由本地程序烘焙，不需要下载外部素材。R19 棚面支持独立 Mesh 替换。

棚架和这组屋顶参数当前用于矩形建筑；茅顶不启用瓦脊/铺瓦选项。抱厦仍只支持筒板瓦，开启抱厦时其它铺瓦选项置灰，CLI 拒绝不支持的组合。塔、连体及抱厦的定制裁切面保持既有瓦纹。梁枋线饰作用于 F02/F05，不覆盖整套历史彩画。旧预设默认不开棚，保持原圆盖脊与筒板瓦；保存后的固定值不被换种子覆盖。

实渲见 `Reference/AncientBuilding_Riverside.png`，设计与参数示例见 Temp §7.5。这些是依据用户所供画面提取的可调美术构造，尚非画中建筑的精确复原。

**街屋样板 v11**：重新加载 `DA_RiversideShop_A`。前脸围护选“敞铺门面”，用“铺面板扇开启”在闭合与折叠开启之间调整，两侧“铺窗柜台高”独立于中间入口。这里只生成可保存的开合位姿，没有运行时交互动画。新增“台沿外扩”“首层柱础高”用于低台街屋；棚杆落地位置跟随台沿边界。

“席面自由挑边”大于 0 时启用 6 mm 薄席，前横杆仍位于既有棚深处，杆外是真实自由边；下垂改变跨中而不移动支承线。“素檐口”使用小飞椽、无卷纹滴水并关闭悬鱼。“街屋柔和材作”统一木、陶瓦、灰墙、石和顺排苇席的表面强度；原材作、其它编织纹样、朱漆、釉瓦及纸绢选择保留各自语义。

样板中的形制与比例已固定，改变种子主要改变席面低频起伏和自由边；不会自动换成花脊或另一种瓦型。需要探索比例时手动调节并保存，取消固定将恢复通用默认的种子变化，尚不是围绕当前样板值的连续随机范围。当前棚没有破洞、扎绳，室内没有商品陈设。最终同机位对照见 `Reference/AncientBuilding_StreetShop.png`，四步实现及美术待验收项见 Temp §5.4、§14.4。

## 预览提交与剔除

预览生成普通 `MeshInstance3D` 并挂到独立 `SubViewport/World3D`。相同 key 共用 Mesh 资源，但这不代表一次渲染提交；Convert 后才用 MultiMesh 做实例批处理。面板显示实例数、唯一网格和渲染节点数，这些数字不是 GPU draw call。材质 surface、深度/阴影等 pass 都会影响实际提交。

视锥剔除由引擎处理。**实墙遮挡剔除（预览）** 默认关闭，勾选后启用 SubViewport 的遮挡系统，并仅从仍为 BoxMesh 的原生 W01 实墙创建向内缩 2% 的 BoxOccluder3D。破损墙、定制裁切墙、板/垒木墙、门洞、透空格心、挂落和外部替换件不作遮挡体。Convert 后 MultiMesh 按整组包围盒剔除，不能逐片瓦剔除；没有承诺固定的性能提升。隐藏面板时预览不持续请求渲染。

遮挡体只服务面板，不烘焙进建筑。关卡的遮挡设置独立配置。面板也不会自动修改关卡中选中的建筑实例，修改后需重新烘焙。

## 默认材质

v13 使用 **BaseColor / NormalGL / ORM** 纹理集：BC 按 sRGB 读取，N 和 ORM 按线性数据读取；ORM 的 R/G/B 分别为 AO、粗糙度和金属度。默认八族为 `Wood`、`WoodEnd`、`Tile`、`Plaster`、`Earth`、`Stone`、`Reed`、`Thatch`，木侧纹与端木纹分开。每族默认三张对齐的 1K 图片，开启 mipmap、重复和各向异性过滤；陶瓦、石材原料不含整片屋面瓦缝或整墙砌块缝。

首次使用或修改源配方后，在仓库根目录运行（制作端需要 Python、NumPy、Pillow）：

```bash
python Tools/AncientBuilding/build_materials.py --engine Engine/bin/godot.windows.editor.x86_64.console.exe
```

`--engine` 是可选的导入步骤：仅导入本次生成的纹理，避免重新扫描历史网格。省略时只烘焙 PNG 与索引，随后让 Godot 编辑器导入。源配方是 `Project/Data/Profiles/AncientBuilding/DA_SurfaceLibrary.json`；输出为 `Project/Generated/AncientBuilding/Materials/<内容摘要>/T_<Family>_{BC,N,ORM}.png`，父目录的 `DA_SurfaceLibrary.json` 为当前索引。可用 `--resolution 2048`、`--seed <整数>` 改变制作参数；不依赖 Blender、Designer 或扫描设备。生成物不提交，新检出或导出游戏前需重建并导入。

木作按构件局部物理尺度定向映射；门框、格扇的横木与竖木具有各自方向语义，破损后保留。柱端使用 `WoodEnd`，不把侧面纵纹折到端面。灰墙、石等使用局部投射，法线按投射基变换；整栋移动或旋转不会令纹理游动。缺少纹理索引或导入结果时使用程序材质回退；外部替换 Mesh 继续使用自己的材质。

在 **建筑形制 → 材质与表面（即时刷新）** 中调整 PBR 开关、法线强度、纹理密度、老化、逐件色差、积灰和表面种子。修改仅刷新共享材质，保留节点、Mesh 与几何任务版本；后台构建完成后也采用最新表面设置。重新烘焙纹理后点击 **重载已烘焙纹理**。这些设置保存到 `building.surface`，与几何变体参数分开；Convert/Revert 保留材质设置及种子。

朱漆露木、釉面、梁饰和编织等既有程序表面细节继续使用。纹理与材质同族共享，局部种子提供受控色差；图像 mipmap 与细纹衰减减少远处闪烁。预览补充天空反射与 SSAO，关卡仍由自身光照决定效果，材质不会自动添加灯光。旧场景须重新烘焙才能采用新的几何与材质契约。

已有实例 shader 参数缓冲约为 4 MiB，修改项目设置后需重启编辑器；预算有限，大批建筑建议 Convert。CLI 的 MultiMesh 转换使用完整数据缓冲，保留实际位姿和表面种子。此前材质图 `Reference/AncientBuilding_Materials.png` 属于旧程序材质阶段；v13 最终画面与限制以 Temp §9.2、§9.3 的实际记录为准，功能通过不等于美术终验通过。

## 替换构件

在 **模块目录** 中选中构件，例如 R05 瓦当，填入可加载的 Mesh 资源路径并点击 **应用此构件的 Mesh**。清空路径再应用即可恢复 PCG。替换件使用自己的表面材质，所有同 ID 实例沿原来的宿主定位。约定单位米，Y 向上。R05 的正 Z 朝檐外，F09 的长轴沿 X，原点在栱底中心。DCC 网格需先导入为独立 Mesh 资源。

预设的 `mesh_overrides` 接受 ID 到路径的映射。手动 `modules` 项可用 `mesh_path` 单独指定。十五份预设可在没有外部美术资产的工程中重建。原有的纯 `modules` 描述仍可加载，摆放旋转字段使用度。定制多边形墙/屋面依赖自己的轮廓和接点，替换时需匹配形状，不能用普通矩形件保证自动适配。

## CLI

```bash
export APPDATA="$(cygpath -w "$PWD/.appdata")"
export LOCALAPPDATA="$APPDATA"
ENGINE=Engine/bin/godot.windows.editor.x86_64.console.exe
CLI=res://addons/ancient_building/cli/main.gd
HALL=res://addons/ancient_building/resources/presets/DA_Hall_A.json
"$ENGINE" --headless --path Project --script "$CLI" -- validate --file "$HALL"
"$ENGINE" --headless --path Project --script "$CLI" -- build --file "$HALL"
"$ENGINE" --headless --path Project --script "$CLI" -- stats --file "$HALL"
"$ENGINE" --headless --path Project --script "$CLI" -- params --out res://addons/ancient_building/PARAMETERS.md
"$ENGINE" --headless --path Project --script "$CLI" -- assembly --file "$HALL"
"$ENGINE" --headless --path Project --script "$CLI" -- bake --file "$HALL"
```

语义与退出码：

- `validate`：只做描述与布局校验，不构建 Mesh；退出码 0/1。
- `build`：构建到内存，不保存场景；会按需写当前版本 Mesh 缓存。
- `stats`：实例、唯一网格、三角面、去重率与按策略统计；不写磁盘缓存。
- `params`：由 `module_catalog.json` 与 `building_variation.gd` 实时生成 [PARAMETERS.md](PARAMETERS.md)；不要手改生成文件。也可用 `bash Tools/AncientBuilding/generate_param_reference.sh` 一步重跑。
- `assembly`：烘焙 `BuildingAssembly` `.tres` 到 `Generated/AncientBuilding/Assemblies/`，并更新 `manifest.json`；占位模块/缺失外部 Mesh 直接报错。
- `bake`：构建并保存旧式逐节点场景；`convert` / `revert` / `inspect` 处理已烘焙场景。
- 退出码：0 成功、1 描述/参数校验失败、2 构建/保存/用法错误。

构件缓存使用 `Generated/AncientBuilding/Meshes/v14/`，被烘焙场景和 assembly 外部引用。盘点与清理用 `.venv/Scripts/python.exe Tools/AncientBuilding/cache_report.py --format md`，确认后再 `--prune --yes --manifest`；它只删旧且未被引用的版本。完整重建顺序见 `Wiki/Temp/008-AncientBuilding.md` §13.5。其他命令有 `list-modules`、`describe --id`、`inspect --scene`。

## 运行时节点

```text
AncientBuildingBatch  (chunk_size)
├─ AncientBuilding    (assembly = Assemblies/*.tres, seed_salt, cast_shadow)
└─ AncientBuilding
```

- `AncientBuilding` 直接引用 assembly；没有祖先 batch 时在自己本地生成 MultiMesh 组，便于单栋/编辑器使用。
- `AncientBuildingBatch` 按 `(chunk, mesh_key, material_profile, cast_shadow)` 跨建筑合并，Mesh 与材质 profile 共享；当前固定 LOD0。
- Dock 的 **烘焙装配体** 与 CLI `assembly` 使用同一个 `AssemblyBaker`；默认输出 `Generated/AncientBuilding/Assemblies/`。
- 新增/删除/移动/改 assembly 时整批重建；这是 P3 的正确性优先实现，逐建筑增量索引后续再做。
- assembly `.tres` 保留完整 `source_descriptor`，可在编辑器中重建；打包阶段可批量转 `.res`。
- 当前没有 LOD、碰撞/导航；`bake` 的旧式场景与 `Convert` 仍然独立可用。

v8 修复此前遗漏的檐口跨构件共面：滴水与封檐板的正面原本同在 54 mm 处，现在封檐板前面收至 8 mm；瓦当按圆盘背面定位，与滴水完整浮雕保留约 9 mm 净距，并以半筒背接瓦垄。曲檐封檐板沿真实檐线生成，邻段留缝、角部斜接，不再加长盒体相互覆盖。带背接的瓦当在破损时保留接触边界。R05 手动参数新增 `neck_length` / `neck_radius`，默认 0 兼容独立单件。
